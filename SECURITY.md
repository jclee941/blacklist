# Security Policy

## Reporting a Vulnerability

Do not open a public issue for an active or exploitable vulnerability.

Use GitHub's private vulnerability reporting form:

<https://github.com/jclee941/blacklist/security/advisories/new>

Include the affected version, reproducible impact, prerequisites, and the smallest safe proof of concept. Do not include production credentials, tokens, personal data, or private infrastructure details.

General hardening suggestions that do not describe an active vulnerability may use the security issue template.

## Supported Versions

Security fixes are released for the latest published version. Operators should upgrade to the latest signed release and verify its checksum and detached signature before installation.
