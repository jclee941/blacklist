# Blacklist 5.1.6 릴리스 노트

## 요약

Blacklist 5.1.6은 오프라인 패키지를 명령 한 번으로 설치할 수 있도록 설치기에 원커맨드 옵션을 추가하고, 제로베이스 설치 검토에서 확인된 설치기 결함을 수정한 패치입니다.

## 주요 변경

- **원커맨드 설치:** `install.sh`가 `--release-key`, `--fingerprint`, `--server-name`, `--tls-cert`, `--tls-key` 옵션을 받습니다. 별도 채널로 받은 fingerprint와 공개키가 일치할 때만 호스트 keyring에 등록하고, 프론트엔드 인증서와 개인키 설치, `FRONTEND_TLS_SERVER_NAME` 설정까지 한 번에 처리합니다.
- **사전조건 일괄 확인:** 이미지 로드와 시크릿 생성 전에 릴리스 keyring, 접속 이름, 인증서와 개인키를 함께 확인하고 부족한 항목을 한 번에 안내합니다. 이 단계에서 중단되면 호스트에는 아무것도 변경되지 않습니다.
- **읽기 전용 사전 검증:** `--verify-only`에 같은 옵션을 넘기면 공개키를 등록하지 않고 매니페스트 서명과 인증서를 미리 검증합니다.

## 수정 사항

- **보안:** 인증 우회와 토큰 위조 취약점(CVE-2026-102268 등 6건)이 공개된 PyJWT를 2.14.0으로 업데이트했습니다.
- **보안:** Redis 이미지 빌드에서 Alpine 패키지를 업그레이드해 OpenSSL 취약점(CVE-2026-75804, CVE-2026-84782)이 수정된 `libssl3`/`libcrypto3` 3.3.7-r2를 사용합니다.
- **인증서 이름 검증:** `openssl x509 -checkhost`/`-checkip`가 불일치에도 0을 반환하는 탓에, 인증서 SAN이 접속 이름을 포함하지 않아도 통과하던 문제를 수정했습니다.
- **초기 관리자 비밀번호 파일:** 시크릿을 생성하는 즉시 `/etc/blacklist/.env.initial-admin-password`(권한 `0600`)를 기록합니다. 이전에는 첫 설치가 중간에 실패하면 재실행해도 파일이 만들어지지 않았습니다.
- **설치 완료 안내:** 관리 명령에 `--env-file`과 `-f` 경로를 포함해 그대로 실행할 수 있게 했고, 접속 주소를 실제 접속 이름으로 표시합니다.
- **설치 출력 정리:** collector 볼륨을 Compose 라벨과 함께 생성해 "was not created by Docker Compose" 경고를 없앴고, DB 역할 구성 출력은 실패할 때만 표시합니다.

## 오프라인 설치 패키지

- `blacklist-5.1.6-release.zip`을 풀고 패키지 디렉터리에서 원커맨드로 설치합니다. 공개키, 인증서, 개인키는 패키지 디렉터리 밖에 둡니다.
- Docker Engine과 Compose는 계속 대상 호스트에 미리 설치해야 합니다. 상세 절차는 패키지의 `docs/blacklist-offline-installation-guide.md`를 따릅니다.

## Breaking Changes

- 없음. 단계별 설치와 업그레이드 절차는 그대로 동작합니다. 다만 인증서 SAN이 `FRONTEND_TLS_SERVER_NAME`을 포함하지 않는 환경은 이제 설치 전에 중단되므로, 업그레이드 전에 인증서를 교체해야 합니다.
