# Blacklist 5.1.8 릴리스 노트

## 요약

Blacklist 5.1.8은 설치 전에 `/etc/blacklist/.env`에 적은 값만으로 설치부터 첫 수집까지 자동으로 진행되게 했습니다. 수집기의 WARP 프록시를 `.env` 스위치로 켜고 끌 수 있고, 수집한 데이터를 담은 설치 패키지를 만들 수 있습니다. 일일 수집이 첫 페이지만 받던 문제도 수정했습니다.

## 새 기능

- **`.env` 사전 지정 설치:** 첫 설치 전에 `/etc/blacklist/.env`에 `ADMIN_PASSWORD`, `REGTECH_ID`/`REGTECH_PW`, `WARP_ENABLED` 같은 값을 적어 두면 설치기가 그 값을 유지하고 빠진 비밀값만 생성합니다. 관리자 비밀번호가 12자 미만이거나 72바이트를 넘으면 파일을 바꾸기 전에 설치를 중단합니다. 지정한 비밀번호는 첫 시작에만 쓰이며, 이후에는 DB에 저장된 값이 기준입니다.
- **REGTECH 계정 자동 등록:** `.env`의 `REGTECH_ID`/`REGTECH_PW`는 저장된 REGTECH 계정이 없을 때 앱이 한 번 암호화해 저장합니다. 대시보드에서 바꾼 계정은 덮어쓰지 않으며, 두 값 중 하나만 있으면 설치기가 거부합니다.
- **최초 3개월 자동 수집:** 수집 데이터가 없는 DB에서 REGTECH 계정이 활성화되면 최근 90일을 최신 구간부터 7일 단위로 한 번 수집합니다. 진행 상태는 `collection_status`의 `REGTECH_INITIAL` 행에 기록되어, 중간에 차단되면 1시간 뒤 마지막 체크포인트부터 이어서 수집합니다. 데이터가 이미 있는 DB는 수집하지 않고 건너뜀으로 기록합니다.
- **WARP 스위치:** 수집기는 `WARP_ENABLED=true`일 때만 REGTECH 요청과 다운로드를 `WARP_PROXY_URL`(비어 있으면 `http://host.docker.internal:40000`)로 보냅니다. 새 설치의 기본값은 꺼짐이고, 설치기는 운영자가 정한 값을 재실행할 때도 유지합니다.
- **데이터 포함 패키지:** `install.sh --export-seed-data <파일>`로 수집 데이터를 내보내고 `scripts/build_offline_bundle.py --seed-data <파일>`로 패키지에 넣을 수 있습니다. 설치기는 서명 검증을 통과한 패키지의 데이터를 빈 DB에만 가져오고, 그 경우 최초 3개월 수집을 건너뜁니다. 다시 만든 패키지는 설치 호스트가 신뢰하는 키로 다시 서명해야 합니다.

## 수정 사항

- **일일 수집 범위:** 매일 02:00 수집이 첫 페이지(최대 50건)만 받던 문제를 수정했습니다. 이제 전날부터 당일까지를 페이지 제한 없이 수집합니다.
- **프론트엔드 이미지 보안 패치:** sharp를 0.35.5(GHSA-wq5f-xc86-pv6w, librsvg CVE-2026-96889)로, source-map-js를 1.2.2(CVE-2026-93749)로 올려 프론트엔드 이미지의 HIGH 취약점 2건을 해소했습니다.

## 업그레이드

- 기존 `/etc/blacklist/.env`, release keyring, 프론트엔드 인증서를 그대로 사용하므로 새 패키지 디렉터리에서 `sudo bash install.sh`만 실행하면 됩니다.
- `.env`에 `WARP_ENABLED`나 `WARP_PROXY_URL`이 없으면 꺼진 값(`false`, 빈 값)으로 추가됩니다. 기존 설치의 WARP 동작은 바뀌지 않습니다.
- 업그레이드 후 수집기는 기존 데이터가 있으면 최초 3개월 수집을 건너뜀으로 기록합니다. 데이터가 없고 REGTECH 계정이 활성화된 설치본은 업그레이드 직후 최초 수집을 시작합니다.

## Breaking Changes

- 없음. 새 동작은 선택 사항이거나 기존 설치의 값과 저장된 계정을 그대로 유지합니다.
