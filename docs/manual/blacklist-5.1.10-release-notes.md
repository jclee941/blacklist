# Blacklist 5.1.10 릴리스 노트

## 요약

Blacklist 5.1.10은 매일 02:00 REGTECH 정기 수집이 수집기 재시작 뒤 아무것도 수집하지 못하던 문제를 고쳤습니다. REGTECH 포털이 점검 중일 때 그 사실을 인증 실패와 구분해 기록하고, 개발용 `make dev` 명령도 최신 Docker Compose에서 다시 동작합니다.

## 수정 사항

- **일일 정기 수집 로그인:** 일일 수집은 수집기 프로세스에 남아 있는 로그인 정보에만 의존했습니다. 이 때문에 기존 데이터가 있어 최초 3개월 수집을 건너뛴 설치에서는 재시작 뒤 수동 수집을 한 번 실행할 때까지 정기 수집이 매일 빈 결과로 끝났습니다. 이제 일일 수집은 DB에 저장된 REGTECH 인증정보로 먼저 로그인합니다.
- **정기 수집 이력 기록:** 일일 수집 결과가 0건이거나 로그인에 실패한 경우에도 `collection_history`에 실행 결과를 남깁니다. 대시보드에서 "실행했으나 0건"과 "실행하지 못함"을 구분할 수 있습니다.
- **REGTECH 점검 감지:** REGTECH 포털이 점검 안내 페이지를 응답하면 로그인 요청을 보내지 않고 인증 실패 횟수도 늘리지 않습니다. 수집 이력과 대시보드 인증 테스트에는 `REGTECH portal under maintenance`와 함께 포털이 안내한 작업 일시가 표시됩니다.
- **개발 환경 명령:** `make dev` 등 Compose를 사용하는 Make 대상이 Docker Compose v5에서 `base.yml`을 찾지 못하던 문제를 고쳤습니다.

## 업그레이드

- 기존 `/etc/blacklist/.env`, release keyring, 프론트엔드 인증서와 Docker 볼륨을 유지하고 새 패키지의 `sudo bash install.sh`를 실행합니다.
- 설정 변경이나 DB 마이그레이션은 없습니다. 업그레이드 뒤 첫 02:00 정기 수집부터 수정된 동작이 적용됩니다.

## Breaking Changes

- 없음. 수집 일정, 수집 범위와 저장 형식은 그대로입니다.
