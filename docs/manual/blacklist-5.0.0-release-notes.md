# Blacklist 5.0.0 릴리즈 노트

정보보호팀 코드검토(2026-07-28) 지적사항을 조치한 보안 릴리즈입니다. 배포 구조가 바뀌므로 기존 설치를 그대로 업그레이드할 수 없습니다. 아래 **업그레이드 절차**를 먼저 확인하십시오.

## 릴리즈 구성

- `5.0.0` 태그와 버전 라벨을 적용한 오프라인 Docker 이미지 5종
- 오프라인 설치 프로그램과 운영 Compose 설정
- 패키지 전체 무결성 목록(`MANIFEST.sha256`)과 이미지 검증 파일
- 한국어 오프라인 배포·운영 가이드

## 업그레이드 절차

기존 4.1.0 설치에서 올릴 때 아래 두 가지를 **설치 전에** 처리해야 합니다.

**1. 환경 파일 이관**

생성된 비밀 파일이 배포 디렉터리 안에서 `/etc/blacklist/.env`로 이동했습니다.

```bash
sudo install -d -m 700 /etc/blacklist
sudo cp <기존 배포 경로>/.env /etc/blacklist/.env
sudo chmod 600 /etc/blacklist/.env
```

이관하지 않으면 설치 프로그램이 기존 배포 상태를 감지하고 새 비밀 생성을 거부합니다.

**2. 추가된 필수 항목 입력**

필수 비밀이 6개에서 9개로 늘었습니다. 기존 환경 파일에 아래 세 항목이 없으면 검증 단계에서 중단됩니다.

```
REDIS_PASSWORD=
COLLECTOR_AUTH_TOKEN=
ADMIN_USERNAME=
ADMIN_PASSWORD=
```

값이 없으면 임의의 긴 문자열을 직접 채우거나, 기존 환경 파일을 백업한 뒤 제거하고 새로 설치해 자동 생성되도록 하십시오. 다만 새로 생성하면 기존 암호화 키가 바뀌어 저장된 자격증명을 복호화할 수 없습니다.

**설치**

```bash
sudo bash install.sh
```

설치 없이 패키지만 점검하려면 `bash install.sh --verify-only`를 사용하십시오. 이 명령은 관리자 권한이 필요 없고 시스템을 변경하지 않습니다.

## 주요 변경

### 네트워크 구조

- 모든 서비스를 내부 bridge 네트워크로 옮기고 host 네트워킹을 제거했습니다.
- 호스트에 공개되는 포트는 frontend `443` 하나입니다. PostgreSQL, Redis, Collector, Flask는 더 이상 호스트에서 접근되지 않습니다.
- 서비스 간 통신은 컨테이너 이름으로 이루어집니다.

방화벽 정책에서 5432, 6379, 8545, 2542에 대한 예외를 두고 있었다면 제거해도 됩니다.

### 전송 구간 암호화

- 대상 서버에서 생성한 자체 인증기관으로 PostgreSQL, Redis, Flask, Collector 구간을 모두 암호화합니다.
- 각 서비스는 상대방 인증서를 검증합니다. 검증을 생략하는 설정은 제공하지 않습니다.
- 인증서는 설치 시 `/etc/blacklist/tls`에 생성되며 패키지에 포함되지 않습니다.
- 브라우저와 frontend 사이의 기존 HTTPS 동작은 그대로입니다.

### 인증

- 관리자 계정 정보를 대상 서버에서 생성하며, 최초 설치 시 화면에 한 번만 표시합니다. 저장해 두고 첫 로그인 후 변경하십시오.
- 관리자 계정 정보가 설정되지 않은 상태에서는 로그인이 불가능합니다. 이전 버전에서는 소스에 포함된 기본값으로 로그인이 가능했습니다.
- Collector 제어 API에 토큰 인증을 적용했습니다. 상태 조회 경로는 헬스체크를 위해 열려 있습니다.

### 패키지 무결성

- 설치 전에 패키지 전체를 SHA-256으로 검증합니다. 무결성 목록이 없으면 설치를 거부합니다.
- Docker 관련 바이너리는 시스템에 반영하기 직전에 다시 검증합니다.
- 검증 대상 파일이 목록에 없거나 목록이 비어 있으면 설치를 중단합니다. 이전 버전은 이런 경우를 통과시켰습니다.
- 서명 검증을 선택적으로 사용할 수 있습니다(`--require-signature`). 공개키는 서버에 미리 배치해야 하며 패키지에는 포함되지 않습니다.

### 설치 프로그램

- 관리자 권한 없이 실행하면 시스템 변경 이전에 중단합니다.
- 설치 시 호스트의 다른 컨테이너를 더 이상 중지하지 않습니다. 이전 동작이 필요하면 `--stop-all-containers`를 사용하십시오.
- 배포 형상이 보안 기준을 위반하면 기동 전에 중단합니다. 긴급 시 `--skip-posture-check`로 우회할 수 있으며 경고가 기록됩니다.
- 서비스 준비 상태를 고정 시간 대기 대신 컨테이너 상태로 확인합니다.
- 여유 공간을 Docker 데이터 디렉터리 기준으로 검사합니다.

### 이미지 관리

- 배포 이미지를 릴리즈 버전으로 고정합니다. 이전에는 `latest`로 다시 태그해 실행 중인 버전을 확인할 수 없었습니다.
- 업그레이드 시 배포 버전이 갱신됩니다. 이전에는 이전 버전 이미지가 다시 기동될 수 있었습니다.
- 동작하지 않던 롤백 파일 생성 코드를 제거했습니다. 롤백은 이전 패키지를 다시 설치하는 방식입니다.

### 수정

- 인증 상태 조회 경로 세 곳이 항상 오류를 반환하던 문제를 수정했습니다.
- 오류 처리 과정에서 원인이 가려지던 문제를 수정했습니다.
- 캐시 서버 인증 정보가 애플리케이션에 전달되지 않던 문제를 수정했습니다.
- 최소 구성 서버에서 이미지 적재가 실패할 수 있던 문제를 수정했습니다.

## 확인 절차

설치 후 아래를 확인하십시오.

```bash
# 서비스 상태
docker compose ps

# 노출 포트 — 출력이 없어야 정상입니다
ss -tuln | grep -E ':(5432|6379|8545|2542)\b'
```

`https://<서버 주소>` 로 접속해 표시된 관리자 계정으로 로그인되는지 확인하십시오.

## 알려진 제약

- 이 패키지에는 Docker 설치 파일이 포함되어 있지 않습니다. 대상 서버에 Docker와 Docker Compose가 미리 설치되어 있어야 합니다.
- 패키지 서명은 아직 적용되지 않았습니다. 검증 기능은 준비되어 있으며 서명 키 발급 후 사용할 수 있습니다.
- 서비스 사이의 통신은 암호화되지만, 같은 서버에 접근 권한이 있는 사용자는 인증서와 환경 파일을 읽을 수 있습니다. 서버 계정 관리가 함께 필요합니다.

## 문의

설치 중 중단되는 경우 화면에 출력된 오류 메시지와 함께 아래 정보를 전달해 주십시오.

```bash
bash install.sh --verify-only 2>&1 | tail -40
docker compose ps
```
