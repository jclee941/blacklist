# Blacklist 5.0.0 릴리스 노트

정보보호팀의 「Blacklist 4.1.0 오프라인 배포 패키지 코드 검토 및 조치 가이드」(2026-07-28)를 기준으로 심각 7건과 중간 8건을 조치했습니다.

## 조치 결과

| 구분                           | 결과                     |
| ------------------------------ | ------------------------ |
| 심각 7건                       | 6건 이행, C-03 부분 이행 |
| 중간 8건                       | 8건 이행                 |
| 조치 과정에서 발견한 추가 결함 | X-01~X-09 이행           |

C-03의 패키지 전체 무결성 검증과 선택적 서명 검증 기능을 구현했습니다. 다만 CI의 분리 서명(detached signature) 생성은 조직 GPG 키 발급 전까지 보류합니다.

## 운영 변경 사항

- 외부 공개 포트는 HTTPS `443` 하나입니다. PostgreSQL `5432`, Redis `6379`, Collector `8545`, Flask `2542`는 호스트에 공개하지 않습니다.
- 대시보드와 애플리케이션 API에는 JWT 인증을 기본 적용합니다. 로그인·health·metrics·정적 자산·명시적 공개 feed만 인증 없이 접근할 수 있습니다.
- 설치 프로그램은 이미지 태그를 `5.0.0`으로 고정하고 `docker compose up --pull never`로 실행하므로 설치 중 레지스트리에 접근하지 않습니다.
- 신규 설치는 대상 호스트에서 관리자 계정과 필수 비밀값을 생성합니다. 업그레이드는 기존 암호화 키를 유지해야 저장된 수집 자격증명을 계속 복호화할 수 있습니다.
- 설치 전 읽기 전용 점검은 `bash install.sh --verify-only`로 실행합니다.
- 설치 프로그램은 Docker 브리지에서 접근 가능한 호스트 WARP 프록시를 자동 감지합니다. 사용할 수 있으면 Collector 프록시를 활성화하고, 없거나 루프백에만 바인딩되어 있으면 `WARP_ENABLED=false`로 기록합니다.

## 확인 방법

```bash
# 설치 없이 번들·이미지 무결성과 배포 포스처 확인
bash install.sh --verify-only

# 설치
sudo bash install.sh

# 공개 포트 확인: 5432·6379·8545·2542가 출력되면 안 됨
ss -tuln | grep -E ':(5432|6379|8545|2542)\b'

# 서비스 상태 확인: 5개 서비스가 healthy여야 함
docker compose ps

# Collector 제어 API: 토큰이 없으면 401
docker exec blacklist-app curl -sk --cacert /run/blacklist/ca.crt \
  -o /dev/null -w '%{http_code}\n' -X POST https://blacklist-collector:8545/trigger
```

| 내용                              | 상태                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| C-03 패키지 분리 서명             | 검증 기능 구현 완료. 조직 GPG 키 발급 후 ADR-0003 절차로 CI 서명 생성 활성화 필요                                            |
| Docker·Compose 오프라인 설치 파일 | 현재 번들은 Docker와 Compose가 설치된 호스트를 전제로 함. 베어 호스트 배포 시 `prereqs/`에 두 파일 모두 추가 필요            |

## 4.1.0에서 업그레이드

기존 설정 파일을 삭제하거나 새로 생성하지 마십시오. 암호화 키가 바뀌면 저장된 수집 자격증명을 복호화할 수 없습니다.

1. 기존 `.env`를 대상 호스트의 `/etc/blacklist/.env`로 이전하고 권한을 설정합니다.
2. `REDIS_PASSWORD`, `COLLECTOR_AUTH_TOKEN`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`를 추가합니다.
3. 오프라인 패키지의 `install.sh`를 루트로 실행합니다.

```bash
sudo install -d -m 700 /etc/blacklist
sudo cp <기존 배포 경로>/.env /etc/blacklist/.env
sudo chmod 600 /etc/blacklist/.env
sudo bash install.sh
```
