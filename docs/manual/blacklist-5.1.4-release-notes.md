# Blacklist 5.1.4 릴리스 노트

## 요약

Blacklist 5.1.4는 2026-09-16 보안 검토(5.1.3 오프라인 배포 번들 정적 분석)에서 확인된 항목을 조치한 보안 패치입니다. 관리자 세션 토큰을 JavaScript가 읽을 수 없는 위치로 옮기고, 응답 CSP에서 인라인 스크립트 허용을 제거했으며, 연결되어 있지 않던 Cloudflare 동기화 경로를 안전장치와 함께 복구했습니다.

## 보안

- 관리자 세션 토큰을 `localStorage`에서 `HttpOnly`·`SameSite=Strict` 쿠키로 옮겼습니다. 브라우저 코드가 토큰을 읽을 수 없으므로 XSS 한 건으로 관리자 세션이 탈취되는 경로가 제거됩니다. 비브라우저 클라이언트를 위한 `Authorization: Bearer` 헤더 경로는 그대로 유지됩니다.
- 프론트엔드 응답 CSP의 `script-src`에서 `unsafe-inline`을 제거하고 요청마다 발급되는 nonce로 대체했습니다.
- Cloudflare 리스트 전량 교체에 규모 급변 가드를 추가했습니다. 직전 리스트 항목 수 대비 30%를 넘는 증감은 전송을 중단하고 경고를 남깁니다.
- Cloudflare 동기화의 rate limit이 변경을 폐기하지 않고 재시도하도록 바꿨으며, 제한 판정 기준을 원격 리스트의 최종 수정 시각으로 옮겨 프로세스 재시작에도 유지되도록 했습니다.
- 암호화되지 않은 Cloudflare 자격 증명 행을 거부합니다. 구버전 마이그레이션이나 수동 DB 편집으로 생긴 평문 토큰은 더 이상 사용되지 않습니다.
- 등록되지 않은 채 번들에 포함되어 있던 평문 자격 증명 저장 라우트와 프리픽스 하한이 없는 CIDR 검증기를 삭제했습니다.
- 수집기 제어 API 인증을 목록 기반에서 기본 거부로 전환했습니다. `/health`를 제외한 모든 경로가 인증을 요구하며, 이후 추가되는 경로도 자동으로 보호됩니다.
- API 오류 응답에서 내부 예외 메시지 노출을 제거했습니다. SQL 문과 테이블·컬럼명이 포함될 수 있는 상세 내용은 로그에만 남습니다.
- REGTECH 인증 캐시 키를 충돌 가능한 내장 해시에서 프로세스별 난수 키를 사용하는 HMAC-SHA256으로 교체했습니다.
- 자격 증명 암호화의 PBKDF2 반복 횟수를 100,000회에서 600,000회로 올렸습니다. 기존 암호문은 계속 복호화됩니다.
- CSV 내보내기의 수식 무력화 대상에 탭과 캐리지리턴을 추가했습니다.
- 의존성 취약점을 해소했습니다. `next` 15.5.25(미인증 RCE 2건), `sharp` 0.35.4(libheif), `vitest`·`@vitest/coverage-v8` 4.1.11(경로 탐색). Python 의존성은 `pip-audit` 결과 알려진 취약점이 없습니다.

## 수정 사항

- Cloudflare 동기화 실행 경로를 연결했습니다. 앱이 변경 알림 리스너를 실행하고, 데이터베이스가 블랙리스트·화이트리스트 변경 시 알림을 발행합니다. 이전에는 연결 테스트만 성공하고 실제 동기화는 일어나지 않았습니다.
- 데이터베이스 IP 형식 제약이 옥텟 범위를 검사하도록 강화했습니다. `999.999.999.999` 같은 값이 저장되어 Cloudflare 일괄 전송 전체를 실패시키는 상황을 막습니다.
- `X-Forwarded-For`를 직접 읽던 잔재를 제거했습니다. 신뢰 프록시 미들웨어가 이미 해당 헤더를 처리합니다.
- 삭제된 설정 화면을 가리키던 레거시 템플릿의 링크를 제거했습니다.
- 설치 프로그램이 최초 로그인 이후 관리자 비밀번호 교체와 `.env` 초기값 무효화를 안내합니다.

## 호환성 변경

- 브라우저 세션 인증이 쿠키 기반으로 바뀌었습니다. 업그레이드 후 기존 브라우저 세션은 무효가 되므로 다시 로그인해야 합니다. API 클라이언트의 bearer token 사용 방식은 바뀌지 않았습니다.

## 업그레이드 참고 사항

- 이 릴리스는 데이터베이스 마이그레이션 두 건(`009`, `010`)을 추가합니다. `configure-runtime-roles.sh`가 적용하므로 기존 설치에 반영하려면 설치 프로그램을 다시 실행해야 합니다. 단순 컨테이너 재시작으로는 적용되지 않습니다.
- 기존 데이터에 옥텟 범위를 위반하는 IP가 있으면 마이그레이션 `010`은 제약을 `NOT VALID` 상태로 남기고 위반 건수를 경고로 출력합니다. 해당 행을 정리한 뒤 `ALTER TABLE ... VALIDATE CONSTRAINT`를 실행하십시오.
- Cloudflare 동기화는 연결 테스트 성공이 아니라 Cloudflare 리스트의 실제 항목 수와 갱신 시각으로 확인하십시오. 자세한 절차는 `docs/manual/security-remediation-2026-09-16.md`에 있습니다.
- 설치 후 관리자 비밀번호를 교체하고 `.env`의 `ADMIN_PASSWORD`를 사용하지 않는 값으로 덮어쓰십시오.
- 설치 전에 서명된 릴리스 번들을 검증하고, 업그레이드 중에는 기존 배포 `.env`, PostgreSQL 데이터 및 TLS 자료를 유지하십시오.
