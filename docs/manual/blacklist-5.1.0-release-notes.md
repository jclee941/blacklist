# Blacklist 5.1.0 릴리즈 노트

REGTECH 수동 수집이 50페이지에서 종료되어 최근 90일 데이터 일부만 저장하던 문제를 수정했습니다.

## 수정 내용

| 항목                | 변경 전                             | 변경 후                           |
| ------------------- | ----------------------------------- | --------------------------------- |
| 수동·강제 수집 범위 | 최근 3개월                          | 최근 90일                         |
| 페이지 제한         | 최대 50페이지                       | 빈 페이지가 반환될 때까지 수집    |
| 페이지 오류         | 빈 페이지로 처리해 부분 저장        | 3회 재시도 후 수집 실패 처리      |
| 반복 페이지         | 계속 수집할 수 있음                 | 반복 응답을 감지해 수집 실패 처리 |
| 앱 수집 timeout     | 호출 경로별 30~90초                 | backend 360초, browser 420초      |
| 관리자 접근         | dashboard API에 인증 없이 접근 가능 | JWT 로그인 후 접근                |
| 일일 자동 수집      | 최근 1일, 1페이지                   | 변경 없음                         |

REGTECH 포털의 실제 페이지 크기는 50건입니다. 기존 제한은 최대 2,500건에서 수집을 중단했습니다. 수정 후 동일 계정의 최근 90일 전체 수집을 실행해 192.98초 동안 11,920건을 수집했으며, 수집 중 들어온 중복 요청은 0.034초 안에 거절했습니다.

## 확인 결과

- 수집 범위: 실행일 기준 최근 90일
- 수집 결과: 11,920건
- 실행 시간: 192.98초
- 동시 중복 요청 거절: 0.034초
- Backend 단위 테스트: 통과
- Backend 통합 테스트: 6개 통과
- Collector 단위 테스트: 통과
- Frontend 단위 테스트: 통과
- 관리자 인증: 미인증 dashboard/API 차단, 로그인 후 접근 확인
- 린트: 통과

## 업그레이드

데이터베이스 스키마 변경은 없습니다. 기존 5.0.0 설치에 5.1.0 이미지를 적용하면 다음 수동 또는 강제 REGTECH 수집부터 최근 90일 전체 페이지를 조회합니다. 장시간 수집 환경에서는 선택적으로 `COLLECTOR_COLLECTION_TIMEOUT`을 조정할 수 있으며 기본값은 360초입니다. Dashboard와 보호 API는 기본적으로 관리자 JWT를 요구하며, 개발 환경에서만 `DISABLE_JWT_AUTH=true`로 명시적으로 해제할 수 있습니다.
