# Blacklist 5.1.9 릴리스 노트

## 요약

Blacklist 5.1.9는 설치 전에 네트워크 충돌을 점검하고 프론트엔드를 공개할 인터페이스와 IP를 단계별로 선택할 수 있게 했습니다. 호스트 NIC를 재설정하지 않고 선택한 주소에만 HTTPS 443 포트를 공개하며, 취소하거나 충돌을 발견하면 기존 서비스를 유지합니다.

## 새 기능

- **읽기 전용 프리스캔:** `install.sh --pre-scan`으로 NIC와 할당 IP, 443 포트 점유, 호스트 및 Docker 서브넷 중복, 내부 IP와 신뢰 프록시 설정을 확인합니다. 파일이나 서비스를 변경하지 않습니다.
- **단계별 네트워크 선택:** 터미널 설치는 프리스캔, 인터페이스 선택, 할당 IP 선택, 최종 확인 순서로 진행됩니다. `--configure-network`로 명시적으로 실행할 수 있고, `0` 또는 `q`, 입력 종료로 취소할 수 있습니다.
- **설치 전 선택 미리보기:** `install.sh --pre-scan --configure-network`는 선택과 최종 확인까지 진행해도 설정을 저장하거나 설치하지 않습니다.
- **무인 설치 주소 지정:** `--interface NAME`과 `--bind-address IP`를 지원합니다. 인터페이스에 사용 가능한 주소가 여러 개면 무인 실행에서는 IP도 지정해야 합니다.

## 수정 사항

- **인터페이스별 포트 검사:** 다른 IP에서 사용 중인 443 포트를 대상 IP의 충돌로 오판하지 않습니다. 호스트 소켓이 없는 Docker 포트 공개도 확인하고, 같은 프로젝트의 기존 프론트엔드 포트는 업그레이드 시 재사용할 수 있습니다.
- **기존 서비스 보호:** 배포 전에 컨테이너 다섯 개를 강제 제거하던 동작을 없앴습니다. 네트워크 검사와 선택을 먼저 끝낸 뒤 Compose가 기존 프로젝트 컨테이너를 갱신합니다.
- **내부 네트워크 일관성:** 서브넷 밖의 프론트엔드 IP, 브리지 게이트웨이와 겹치는 IP, 프론트엔드를 포함하지 않는 신뢰 프록시 범위를 설치 전에 거부합니다. 기존 프로젝트 브리지의 서브넷 변경도 자동으로 진행하지 않습니다.
- **호스트 Python 호환성:** 네트워크 도우미는 애플리케이션 컨테이너의 Python 버전에 의존하지 않으며, 구버전 호스트에서 실행할 수 있는 구문과 표준 라이브러리를 사용합니다.

## 사용 방법

압축을 푼 패키지 디렉터리에서 먼저 읽기 전용 점검과 선택 미리보기를 실행합니다.

```bash
sudo bash install.sh --pre-scan
sudo bash install.sh --pre-scan --configure-network
```

첫 설치는 기존과 같이 공개키, fingerprint, 접속 이름, 인증서와 개인키를 함께 지정합니다. 터미널에서 실행하면 네트워크 선택 절차가 이어집니다.

## 업그레이드

- 기존 `/etc/blacklist/.env`, release keyring, 프론트엔드 인증서와 Docker 볼륨을 유지하고 새 패키지의 `sudo bash install.sh`를 실행합니다.
- 터미널에서는 기존 바인딩 유지 또는 다른 NIC의 할당 주소를 선택할 수 있습니다. 무인 실행은 저장된 바인딩을 유지하며, 새 무인 설치에 별도 설정이 없으면 기존 기본값인 `0.0.0.0`을 사용합니다.
- `ip`와 `ss`가 필요합니다. 두 명령은 iproute2 패키지에서 제공합니다.
- 설치기는 호스트 NIC의 주소·링크·라우팅·방화벽 설정을 직접 재설정하지 않습니다. 애플리케이션 브리지와 포트 공개에 필요한 네트워크 처리는 Docker가 관리합니다.

## Breaking Changes

- 없음. 기존 무인 설치와 유지보수 명령을 계속 지원합니다.
